# NV Timeline 使用手册

本文面向在 Godot 项目中使用 NV Timeline 的程序与策划，说明插件如何安装、编辑编排文件、接入业务回调，以及如何理解时间轴运行行为。插件的内部类结构和源码维护方式见[时间轴插件开发手册](时间轴插件开发手册.md)。

## 1. 插件能做什么

NV Timeline 将静态编排和游戏业务分开：策划在 `.timeline.json` 中编辑时钟、唯一时间轴、多条轨道、视觉片段和标签标记；程序创建 `NVTimelineService`，注册标签对应的 Godot `Callable`，然后启动或推进时间轴。

插件负责按时间求值、发出标签、等待阻塞输入、派发请求，以及在配置要求时等待业务返回成功或失败。具体的游戏逻辑、UI、玩家选择、输入校验、AI 调用和异步任务都由项目代码负责。

当前功能边界：

- 一个 `.timeline.json` 文件中恰好包含一条时间轴。
- 一个 `NVTimelineService` 当前加载一份文档；多文件同时加载到同一 Service 是后续扩展。
- 一份文档可以有多个时钟定义，但其唯一时间轴只绑定其中一个时钟。
- 片段是纯视觉对象，不会在片段起点、终点或播放头经过时调用代码。
- 时间精度固定为 0.1 秒。文件不保存运行游标、消息队列、Callable 或游戏进度。

## 2. 安装和打开编辑器

1. 使用与插件构建版本兼容的 Godot 4.8 打开项目。
2. 确认 `addons/nv_timeline/bin/<platform>/` 下存在当前平台的原生库，并且 `addons/nv_timeline/nv_timeline.gdextension` 指向该库。
3. 在“项目 > 项目设置 > 插件”中启用 `NV Timeline`。
4. 从“项目 > 工具 > NV Timeline”打开独立编辑窗口。
5. 点击“打开”，选择 `res://addons/nv_timeline/examples/basic.timeline.json` 作为示例。

如果刚构建过原生扩展，关闭并重新打开编辑器。当前扩展声明为不可热重载；重启也有助于确认 Godot 实际加载的是新库。

新建文档会创建一个手动时钟、一条不限时长的空时间轴。保存时建议使用 `.timeline.json` 后缀，并将策划数据纳入版本控制。

## 3. 编辑器操作

### 文档、时钟和时间轴

- **新建、打开、保存、另存为**管理 JSON 文件。存在未保存修改时，切换文档或关闭窗口会先询问是否放弃修改。
- 左侧**逻辑时钟**选择器用于选择时钟；加号新增时钟，减号删除当前时钟。被时间轴引用的时钟不能删除。
- 选择时间轴名称或使用左侧“文档属性”入口，在属性面板设置时间轴名称、绑定时钟和时长。
- 勾选“不限时长”表示没有预设结束位置，不表示循环。有限时长使用 0.1 秒整数单位；例如 `40` 表示 4.0 秒。
- 有限时长右侧的灰色区域表示超出有效编排范围。标记不能超过终点，片段必须完整落在有效范围内。

### 轨道和对象

- **新增轨道**创建一条轨道；选择轨道后可删除、上移、下移或切换启用状态。数组顺序就是从上到下的显示顺序和同刻标记的轨道顺序。
- 右击轨道表头或画布中的轨道，可打开菜单新增片段、输出标记或阻塞输入标记。
- 也可以在编辑工具栏新增片段、输出标记或阻塞输入。新增对象使用当前播放头位置和当前选中的轨道；没有可用轨道时，编辑器会先新增轨道。
- 同一轨道的片段不能重叠。新增片段会寻找下一个空闲区间；需要并行片段时，放到不同轨道。
- 片段与标签标记可以在同一轨道、同一时间位置。标记之间也可以同刻重叠，编辑器会在该轨道内错开展示。
- 拖动片段中部可以移动片段；拖动片段左右边缘可以缩短或拉长。移动或调整长度时，编辑器会遵守轨道边界、时间轴时长和相邻片段的限制。
- 标签标记显示在轨道内的时间竖线上。拖动标记可以改时间；选中后在属性面板修改名称、时间、标记类型和标签。
- 选中输出标记后，属性面板中的“等待业务结果”开关可令时间轴发出标签后暂停，直到程序返回成功或失败；切换为阻塞输入时该开关会隐藏。
- 左侧**全程输入**列表用于新增、选择和删除无具体时间点的输入。属性面板可以修改名称、标签和启用状态。
- 片段、标记或全程输入被选中时，可点击属性面板的删除按钮；画布片段和标记也支持 `Delete` 与 `Backspace`。文本输入控件正在处理按键时不会删除画布对象。
- **撤销/重做**恢复成功提交的文档编辑，最多保留最近 100 次编辑。播放头、缩放和选择状态属于编辑器会话状态，不进入撤销数据或 JSON。

### 标尺、播放头和属性应用

- 时间标尺每 1.0 秒显示文字，鼠标吸附单位为 0.1 秒。
- 在上方标尺单击或按住拖动可定位红色播放头。轨道空白处单击不会改动播放头。
- 选中对象后，在右侧修改字段，再点击“应用属性”提交；非法值会被文档校验拒绝，原有文档数据保留。
- 内部 ID 由编辑器分配和维护，不需要策划填写，也不会作为普通属性显示。

更细的窗口验收步骤见[时间轴可视化编辑器验收说明](时间轴可视化编辑器验收说明.md)。

## 4. 设计一份编排

### 时间单位

时间字段都使用非负整数，1 单位 = 0.1 秒：

| 单位数 | 秒数 |
|---:|---:|
| 1 | 0.1 |
| 10 | 1.0 |
| 35 | 3.5 |
| 100 | 10.0 |

时间轴有限时长、标记 `time`、片段 `start` 和片段 `duration` 使用同一单位。`realtime` 时钟的 `rate` 是倍率，不是时间单位。

### 对象含义

| 对象 | 用途 | 是否调用业务逻辑 |
|---|---|---|
| 时钟 | 决定时间轴由程序手动推进，还是按真实经过时间推进 | 否 |
| 轨道 | 组织对象、控制显示顺序，并可整体启用或禁用 | 否 |
| 片段 `clip` | 显示某段内容、阶段或素材的时间范围 | 否 |
| 输出 `output` | 到达位置时发出一个标签 | 通过程序注册的 Callable |
| 阻塞输入 `blocking` | 到达位置时检查是否已收到期待标签；未收到则等待 | 等待逻辑由插件执行 |
| 全程输入 `listener` | 时间轴运行期间随时接收指定标签 | 通过程序注册的 Callable |

如果要在片段开始和结束时执行逻辑，请在相应时间放置两个输出标记，分别发出开始和结束标签。片段不会自动驱动这些标签。

### 最小 JSON 示例

```json
{
  "name": "第一章",
  "id_counter": 7,
  "clocks": [
    { "id": 1, "name": "剧情时钟", "mode": "manual" }
  ],
  "timelines": [
    {
      "id": 2,
      "name": "第一章流程",
      "clock_id": 1,
      "duration": 100,
      "tracks": [
        {
          "id": 3,
          "name": "主流程",
          "enabled": true,
          "clips": [
            { "id": 4, "name": "解谜阶段", "start": 0, "duration": 100, "color": "#568AC8" }
          ],
          "marks": [
            { "id": 5, "name": "开始解谜", "time": 0, "kind": "output", "label": "puzzle_start" },
            { "id": 6, "name": "等待完成", "time": 50, "kind": "blocking", "label": "puzzle_completed" }
          ]
        }
      ],
      "listeners": [
        { "id": 7, "name": "紧急中断", "label": "urgent_interrupt", "enabled": true }
      ]
    }
  ]
}
```

示例表示：启动时发出 `puzzle_start`；时间轴到 5.0 秒时检查本次运行是否收到 `puzzle_completed`，没有则在该时间等待；`urgent_interrupt` 在本次运行期间持续作为输入入口。示例中的片段只供策划查看阶段范围。

### 标签命名

标签是大小写敏感的完整字符串，例如 `puzzle_completed` 与 `Puzzle_Completed` 是两个不同标签。标签不能是空字符串，也不能带首尾空白。相同标签可以被多个标记或输入使用；一条收到的标签可同时解除同名的多个有效阻塞输入。

JSON 保存实际使用的标签，但不保存标签处理代码。即使程序里尚未注册某个标签，编排文件仍可通过结构校验；运行时接入由程序负责。

## 5. 运行时接入

### 创建 Service 并加载文档

`NVTimelineService` 是普通 Godot `Node`，可以挂在场景树中，也可以由项目作为 Autoload 管理。每个 Service 管理一份当前文档和该文档的时钟、时间轴运行实例。

```gdscript
extends Node

var timeline_service: NVTimelineService

func _ready() -> void:
	# Service 在游戏节点暂停时仍可驱动 realtime 时钟。
	timeline_service = NVTimelineService.new()
	add_child(timeline_service)
	timeline_service.diagnostic.connect(_on_timeline_diagnostic)

	# 先注册程序绑定，再加载并启动编排。
	var manager := timeline_service.get_event_manager()
	manager.register_binding("puzzle_start", Callable(self, "_on_puzzle_start"))
	manager.register_binding("puzzle_completed", Callable(self, "_on_puzzle_completed"), true)

	if not timeline_service.load_json_file("res://chapter_01.timeline.json"):
		push_error("时间轴加载失败：%s" % timeline_service.get_diagnostics())
		return

	# 示例文件中的时间轴 ID 是 2。
	timeline_service.submit_request({
		"type": "start_timeline",
		"timeline_id": 2,
	})

func _on_puzzle_start(context: Dictionary) -> void:
	print("开始解谜，时间：", context.get("time_units", 0) * 0.1, " 秒")

func _on_puzzle_completed(context: Dictionary) -> void:
	print("收到解谜完成输入：", context.get("label", ""))

func _on_timeline_diagnostic(message: String) -> void:
	push_warning("NV Timeline: " + message)
```

`requires_timeline_input` 默认为 `false`。普通绑定接收匹配标签的派发消息；传入 `true` 后，只有至少一条运行中的时间轴实际接受了该标签（例如命中了有效的阻塞输入或全程输入）时，才调用该绑定。

### C# 接入

当前 C# 使用 Godot 动态对象 API 调用自定义 GDExtension 类：通过 `ClassDB.Instantiate` 创建 Service，通过 `GodotObject.Call` 调用插件方法，并使用 `Callable.From<Dictionary>` 注册一个接收 Godot 字典的委托。项目不需要假定插件已经生成了自定义 C# 静态包装类。

```csharp
#nullable enable

using Godot;
using Godot.Collections;

public partial class TimelineBootstrap : Node
{
	private Node _service = null!;

	public override void _Ready()
	{
		GodotObject? serviceObject = ClassDB.Instantiate("NVTimelineService").AsGodotObject();
		if (serviceObject is not Node serviceNode)
		{
			GD.PushError("无法创建 NVTimelineService。");
			return;
		}
		_service = serviceNode;
		AddChild(_service);

		GodotObject? manager = _service.Call("get_event_manager").AsGodotObject();
		if (manager is null)
		{
			GD.PushError("NVTimelineService 没有返回事件管理器。");
			return;
		}
		manager.Call(
			"register_binding",
			"puzzle_start",
			Callable.From<Dictionary>(OnPuzzleStart),
			false);

		if (!_service.Call("load_json_file", "res://chapter_01.timeline.json").AsBool())
		{
			GD.PushError("时间轴加载失败。");
			return;
		}

		var request = new Dictionary
		{
			["type"] = "start_timeline",
			["timeline_id"] = 2,
		};
		_service.Call("submit_request", request);
	}

	private void OnPuzzleStart(Dictionary context)
	{
		string label = context.ContainsKey("label") ? context["label"].AsString() : "";
		GD.Print($"收到标签：{label}");
	}
}
```

该互操作方式已用项目中的 `test/NVTimelineCallableInteropTest.tscn` 实际运行验证。使用具体 C# 版本前，应先用当前项目的 Godot Mono 版本构建 C# 程序集。

## 6. 统一请求入口

程序可以调用 `service.submit_request(Dictionary)` 提交标签、时间轴控制、时钟推进、快进、跳转和输出结果。所有回调中产生的后续操作都应走这个入口。返回 `true` 表示请求字段结构合法并已进入队列，不表示目标时间轴一定存在或操作最终成功；目标运行错误通过诊断信号报告。

| `type` | 必填字段 | 可选字段 | 作用 |
|---|---|---|---|
| `publish_label` | `label: String` | `target_timeline_id: int`、`source_timeline_id: int`、`source_run_id: int`、`input_id: int`、`time_units: int`、`output_mark_id: int`、`wait_for_result: bool` | 发布标签；目标 ID 省略或为 0 时广播 |
| `start_timeline` | `timeline_id: int` | | 启动并创建本次运行状态 |
| `pause_timeline` | `timeline_id: int` | | 暂停时间轴推进 |
| `resume_timeline` | `timeline_id: int` | | 恢复时间轴；若仍在等待输入，不会越过等待点 |
| `stop_timeline` | `timeline_id: int` | | 停止本次运行并清除其接收记录 |
| `advance_clock` | `clock_id: int`、`units: int` | | 手动推进时钟，`units` 必须为正数 |
| `fast_forward` | `timeline_id: int`、`target_units: int` | | 按顺序求值至绝对位置，遇阻保留目标 |
| `jump` | `timeline_id: int`、`target_units: int` | | 向前跳至绝对位置，略过目标位置及之前的标记 |
| `resolve_output_result` | `timeline_id: int`、`run_id: int`、`mark_id: int`、`success: bool` | | 返回等待结果的输出标记成功或失败 |

示例：

```gdscript
# 快进到 8.0 秒；target_units 是绝对时间，不是要增加的时长。
timeline_service.submit_request({
	"type": "fast_forward",
	"timeline_id": 2,
	"target_units": 80,
})

# 发给特定时间轴；不指定目标时是广播。
timeline_service.submit_request({
	"type": "publish_label",
	"label": "puzzle_completed",
	"target_timeline_id": 2,
})
```

请求队列内部使用 `label` 表示已经产生的标签消息，但它是内部类型，不能作为 `submit_request` 的公开请求提交。外部发标签应使用 `publish_label`。

Service 仍保留 `start_timeline`、`pause_timeline`、`resume_timeline`、`stop_timeline`、`advance_clock` 和 `publish_label` 便捷方法以兼容直接调用；在标签 Callable 回调中应使用 `submit_request`，使回调产生的控制操作按 FIFO 安全派发。

## 7. 阻塞和时间推进规则

### 阻塞输入 `blocking`

时间轴到达阻塞标记时，如果本次运行尚未收到同名标签，就进入等待状态并停在标记时间。标签可以在到达标记之前到达；只要时间轴当时处于活动状态，运行时会记住本次运行已收到的标签，之后到达标记即可通过。停止或重新启动会清除旧运行的标签记录。

暂停、等待期间，全程输入和有效阻塞输入仍可以接收标签。收到等待标签只解除等待，不会取消显式暂停；如果先前被暂停，程序还需提交 `resume_timeline`。

普通 `advance_clock` 遇到阻塞时，所属时间轴停在阻塞点，本次剩余推进量会丢弃；共享该时钟的其他时间轴不因它而自动停止。显式 `fast_forward` 遇到阻塞则保留目标，阻塞解除后继续按序处理直到目标或下一个阻塞点。

### 等待业务结果的输出

普通输出只发标签，不等待。将输出标记设为 `wait_for_result: true` 后，输出标签仍会发出，但所属时间轴会停在该标记，等待业务代码提交 `resolve_output_result`：

- `success: true`：解除等待并继续处理后续标记。
- `success: false`：停止本次运行。

等待上下文包含 `source_timeline_id`、`source_run_id`、`output_mark_id` 和 `wait_for_result: true`。返回结果时依次把它们映射到 `timeline_id`、`run_id` 和 `mark_id`。

```gdscript
func _on_puzzle_start(context: Dictionary) -> void:
	if not context.get("wait_for_result", false):
		return

	# 实际游戏中可在玩家完成 UI 操作后再提交此请求。
	var result_request := {
		"type": "resolve_output_result",
		"timeline_id": context["source_timeline_id"],
		"run_id": context["source_run_id"],
		"mark_id": context["output_mark_id"],
		"success": true,
	}
	timeline_service.submit_request(result_request)
```

业务的细分结果不作为插件返回值。例如成功、失败、不同密码等分支由业务代码决定并发布不同标签；插件只等待布尔成功或失败。对于等待结果的输出，必须确保项目确实处理该标签并最终返回结果，否则时间轴会一直等待。重新启动产生新的 `run_id`，旧异步操作迟到的结果会被拒绝。

### 快进与跳转

- `fast_forward` 的目标是时间轴的绝对位置。它按顺序触发期间输出并检查阻塞；如果遇到需要玩家操作的阻塞，会正常停下。成功解除后继续到原目标。
- `jump` 只允许向前，直接移动时间轴并略过目标位置及之前的标记，不补发标签，也不等待经过的阻塞输入。到达有限时长末端时可以完成时间轴。

## 8. 状态观察与诊断

`service.get_timeline_ids()` 和 `service.get_clock_ids()` 返回当前文档的 ID 列表；使用 `get_timeline(id)`、`get_clock(id)` 查询运行对象。时间轴提供 `get_position()`、`get_duration()`、`get_run_id()`、`get_state_name()`、`is_waiting()` 和 `is_waiting_for_output_result()` 等方法。时间单位仍为 0.1 秒。

Service 可监听以下信号：

| 信号 | 用途 |
|---|---|
| `timeline_started(timeline_id, run_id)` | 一次时间轴运行启动 |
| `timeline_paused(timeline_id)` | 时间轴暂停 |
| `timeline_stopped(timeline_id, run_id)` | 时间轴停止；包括业务返回失败的停止 |
| `timeline_completed(timeline_id, run_id)` | 有限时长到达末端且标记已处理完毕 |
| `label_emitted(label, timeline_id, time_units)` | 时间轴输出标记发出标签 |
| `diagnostic(message)` | 文档、请求或运行期间的诊断 |

`label_emitted` 用于观察时间轴输出标记，不是所有外部 `publish_label` 请求的全量消息监听器。详情可通过 `get_diagnostics()` 查看，并用 `clear_diagnostics()` 清空。

## 9. 常见问题

**菜单中没有 NV Timeline。** 检查项目插件是否启用，并确认插件脚本 `addons/nv_timeline/editor/nv_timeline_plugin.gd` 和 `plugin.cfg` 路径有效。

**提示找不到 `NVTimelineService` 或编辑窗口类。** 原生 GDExtension 没有成功加载。检查 Godot 版本、当前平台 DLL/SO 路径和依赖，并在重建后重启编辑器。

**标记处没有执行项目逻辑。** 检查标签大小写和空白、Callable 是否在启动前注册、轨道是否启用，以及绑定是否设置了 `requires_timeline_input=true`。后者要求运行中的时间轴确实接受了该标签。

**时间轴停在某个位置。** 检查该处是否有未满足的 `blocking` 输入，或是否有设置 `wait_for_result` 的输出没有收到结果。可读取 `get_state_name()`、等待标记 ID 和诊断信息。

**片段边界没有调用函数。** 这是预期行为。片段只绘制范围；请在需要执行逻辑的时间位置添加输出标记，并在程序中绑定对应标签。

**C# 找不到 `NVTimelineService` 类型。** 自定义原生类不一定有静态 C# 类型包装。可用 `ClassDB.Instantiate("NVTimelineService")` 创建，通过 `GodotObject.Call` 调用方法，并用 `Callable.From<Dictionary>` 注册回调，见本手册的 C# 示例。
