# 时间轴 JSON 表示技术方案

状态：设计方案，尚未实现。

关联文档：[时间轴事件系统技术方案](时间轴事件系统技术方案.md)。

## 1. 已确认的设计约束

JSON 保存可视化时间轴的编排结果，包括纯视觉的事件段，以及全部输出标签、带时间点的阻塞输入标签、无时间点的全程输入标签。

视觉事件段在程序中称为 TimelineClip，字段使用 clips；事件系统中的处理实例称为 EventHandler。两者是独立概念。视觉事件段进入 JSON，标签与处理类的绑定、处理类定义、处理实例和业务事件生命周期由程序管理，不进入 JSON。可视化编辑器不能修改这些程序绑定。

其他已确认约束：

- 不设置 schema_version。
- 不设置 timebase，时间精度固定为 0.1 秒。
- 所有配置对象的 id 使用程序生成的 int，共用文档级自增计数器 id_counter；自增结果为负数时，报错并拒绝分配。
- 时钟只有 manual 和 realtime 两种模式，不设置 external。
- 多个时间轴对等，可以同时存在。是否共享时间来源由时钟绑定决定。
- 视觉事件段是类似剪辑软件素材的段落，可配置开始位置、长度、名称和颜色，只用于可视化组织。
- 输出标记只发出一个标签，不配置脚本、方法、目标或业务参数。
- 阻塞输入具有具体时间点。到达该时间点时，如果尚未收到期待的标签，时间轴等待。
- 全程输入没有具体时间点，在编辑器的固定输入区域显示。
- 当前方案不包含 AI 知识、游戏进度存档、网络同步等扩展。

下文给出覆盖这些约束的完整字段建议。文件组织方式、字段名称、默认值和校验规则属于本次技术方案的落地建议；尚未确定的运行行为列在最后一节。

## 2. JSON 与可视化的对应关系

| 可视化内容 | JSON 位置 | 保存的信息 |
|---|---|---|
| 文档名称 | name | 编辑器显示的文档名称 |
| 时钟配置列表 | clocks | 时钟标识、名称、驱动模式、实时倍率 |
| 时间轴列表与属性 | timelines | 时间轴标识、名称、时钟绑定、时长 |
| 轨道 | timelines[].tracks | 轨道标识、名称、启用状态、排列顺序 |
| 纯视觉事件段 | tracks[].clips | 段落标识、名称、开始位置、长度、颜色 |
| 输出标签标记 | tracks[].marks，kind 为 output | 标记标识、名称、时间位置、输出标签 |
| 阻塞输入标签标记 | tracks[].marks，kind 为 blocking | 标记标识、名称、时间位置、期待的输入标签 |
| 全程输入标签 | timelines[].listeners | 输入标识、名称、标签、启用状态 |

字段 label 在三种标签配置中都存在。listeners 仅表示无具体时间点的全程输入，不是整份文档的标签总表。

完整标签使用清单可以通过遍历所有 marks 和 listeners 得到。当前结构不额外保存一份重复的标签总表，避免总表和实际编排不一致。

clips 不包含输入或输出标签。片段可以与标签标记出现在同一轨道，但位置上的覆盖关系不会建立业务绑定，也不改变全部标签仍由 marks 和 listeners 保存的规则。

程序可以提供只读的标签说明、处理类型说明和绑定状态，帮助编辑器选择和检查标签。当前编排实际使用的标签仍然由 JSON 保存，不依赖程序目录来补全。

标识 id 可以在编辑器属性中只读查看，由程序生成，策划不能修改。id_counter 是程序管理的文档分配元数据，不属于业务事件配置。滚动位置、窗口位置、临时选中项等编辑器会话状态不属于时间轴编排。

### 2.1 独立编辑窗口

时间轴编辑器采用类似 Unity 插件的独立弹出窗口作为主要编辑界面。用户从 Godot 编辑器的插件入口打开窗口，窗口以非模态方式独立移动和调整大小，同时保留 Godot 主编辑器的可用性。

窗口中的时间轴、轨道、视觉事件段、标签标记、全程输入和属性编辑直接对应本文件的 JSON 字段。窗口关闭、切换文档或切换时间轴时，应先处理未保存修改。

窗口位置、大小、滚动位置、缩放比例和临时选中对象属于编辑器会话状态，不写入 JSON。打开或关闭窗口也不代表启动、暂停、停止或修改时间轴运行实例。

## 3. 文件组织与时间表示

### 3.1 文档组织

建议一个 JSON 文件保存一份时间轴文档，文档中包含时钟列表和一个或多个时间轴。单条时间轴也使用同样的结构。

建议文件名使用 .timeline.json 后缀，例如 chapter_01.timeline.json。文件正文使用 UTF-8 编码和标准 JSON 语法。

时间轴之间没有父子关系，不使用 global、local 或嵌套时间轴字段。多条时间轴放在同一个 timelines 数组中。

### 3.2 固定时间单位

所有时间字段使用非负整数，1 个单位等于 0.1 秒。

| JSON 数值 | 编辑器显示 |
|---|---|
| 0 | 0.0 秒 |
| 1 | 0.1 秒 |
| 35 | 3.5 秒 |
| 100 | 10.0 秒 |

标记 time、片段 start、片段 duration 和时间轴 duration 均使用该单位。实时倍率 rate 是无量纲数值，可以使用小数。

编辑器的时间吸附精度为 0.1 秒。运行时仍然逐帧更新，积累不足一个单位的经过时间，不要求游戏帧率为每秒 10 帧。

## 4. 根对象

### 4.1 字段定义

| 字段 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| name | string | 否 | 文件名 | 文档显示名称 |
| id_counter | int | 是 | 新文档为 0 | 最后一次成功分配的配置对象 ID |
| clocks | array | 是 | 无 | 时钟定义列表 |
| timelines | array | 是 | 无 | 对等时间轴定义列表 |

clocks 和 timelines 可以为空，便于创建尚未编排的文档。存在时间轴时，其引用的时钟必须存在。

根对象不包含事件管理器、处理类、标签绑定表或运行时状态。

### 4.2 文档级 ID 分配

id 和 id_counter 使用有符号 32 位 int，与 C# int 一致；JSON 中写为普通整数。0 保留为未分配值，实际对象 ID 从 1 开始。

clock、timeline、track、clip、mark、listener 共用同一份文档的计数器。分配流程为：

~~~text
计算 id_counter 自增一次后的 int 值
如果结果为负数：报错，拒绝本次分配
否则：将结果写回 id_counter，并作为新对象的 id
~~~

溢出只按“自增结果为负数”检查，不另做最大值预判。失败时不写入负数 ID 或计数器。实现时必须取得确定的 int 回绕结果；C# 可以使用 unchecked，C++ 不直接依赖有符号溢出行为。

删除对象不减少计数器，已分配的 ID 不重新使用，不要求 ID 连续。撤销创建不退回计数器，重做可以恢复原对象及其原 ID。

复制、粘贴或合并其他文档的对象时，为新对象重新分配 ID，并同步改写 clock_id 等内部引用。clock_id 是引用已有时钟的 ID，本身不申请新 ID。

加载文档时恢复已保存的 id_counter，保存时保留其当前值，不根据现存对象重新压缩或编号。该计数器只保证单份文档内唯一，不承担跨文件唯一性。

name 和 label 继续使用字符串。程序中的时间轴运行标识、事件执行标识与绑定标识不消耗此计数器，也不写入 JSON。

## 5. 时钟定义

| 字段 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| id | int | 是 | 程序分配 | 文档内唯一的时钟标识 |
| name | string | 否 | id 的文本形式 | 时钟显示名称 |
| mode | string | 是 | 无 | manual 或 realtime |
| rate | number | 否 | 1.0 | 实时推进倍率，只适用于 realtime |

manual 接收程序中的推进请求。realtime 根据经过的实际时间自动推进。

rate 必须大于 0。manual 时不填写 rate，编辑器也不显示该配置项。

当前时间位置、暂停状态和累计的不足 0.1 秒时间都属于运行时状态，不写入定义文件。

~~~json
{
  "id": 2,
  "name": "桌面时钟",
  "mode": "realtime",
  "rate": 1.0
}
~~~

## 6. 时间轴定义

| 字段 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| id | int | 是 | 程序分配 | 文档内唯一的时间轴定义标识 |
| name | string | 否 | id 的文本形式 | 时间轴显示名称 |
| clock_id | int | 是 | 无 | 引用本文件的某个时钟 |
| duration | integer 或 null | 否 | null | 显示的时间轴时长；null 表示不限时长 |
| tracks | array | 是 | 无 | 轨道列表 |
| listeners | array | 是 | 无 | 无具体时间点的全程输入标签列表 |

有限 duration 必须大于 0，编辑器显示对应的结束位置。所有轨道标记的 time，以及视觉事件段的 start + duration，不得超过时间轴的有限 duration。

不限时长表示时间轴没有预设结束位置，需要由程序结束本次运行。不限时长不等同于循环。

多条时间轴使用同一个 clock_id，表示共享时间来源。使用不同的 clock_id，表示独立时间来源。时间轴之间的调用和通信由事件系统处理，不保存其他时间轴对象引用或调用脚本。

JSON 中的 id 标识配置定义。运行时可以从同一份定义创建多个实例，实例标识和本次运行标识由程序生成。

## 7. 轨道定义

| 字段 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| id | int | 是 | 程序分配 | 文档内唯一的轨道标识 |
| name | string | 否 | id 的文本形式 | 轨道显示名称 |
| enabled | boolean | 否 | true | 是否参与运行时编排 |
| clips | array | 否 | 空数组 | 纯视觉事件段列表 |
| marks | array | 是 | 无 | 有具体时间点的标记列表 |

tracks 数组顺序对应编辑器中从上到下的轨道顺序，不额外设置 order 字段。

同一轨道允许多个标记位于同一时间点，不设置互斥规则。禁用轨道保留其全部标记，但运行时不参与输出和阻塞输入处理。

同一轨道也允许多个视觉事件段重叠。只用于视觉组织的轨道可以保留空 marks 数组。禁用轨道时仍保存其 clips，编辑器可以通过灰显等方式提示轨道状态。

marks 建议按 time 升序保存。同一时间点的标记保留编辑器确定的稳定顺序。

## 8. 纯视觉事件段

### 8.1 字段定义

视觉事件段保存在所属轨道的 clips 数组中。clips 与 marks 并列，不是标签标记的父节点。

| 字段 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| id | int | 是 | 程序分配 | 文档内唯一的视觉事件段标识 |
| name | string | 是 | 无 | 编辑器中显示的段落名称 |
| start | integer | 是 | 无 | 开始位置，单位为 0.1 秒 |
| duration | integer | 是 | 无 | 段落长度，单位为 0.1 秒，必须大于 0 |
| color | string | 否 | #568AC8 | 编辑器显示颜色，使用 #RRGGBB 格式 |

start 必须是非负整数，duration 必须是正整数。显示范围为 [start, start + duration)，不另存 end。clips 建议按 start 升序保存，开始位置相同时保留编辑器确定的稳定顺序。

### 8.2 示例

~~~json
{
  "id": 5,
  "name": "解谜阶段",
  "start": 100,
  "duration": 200,
  "color": "#568AC8"
}
~~~

含义：编辑器在 10.0 秒到 30.0 秒之间显示一块名为“解谜阶段”的段落。拖动段落修改 start，拖动边缘修改 start 或 duration，改名或改颜色修改对应字段。

### 8.3 与事件系统及标签的边界

视觉事件段不发出标签，不创建事件处理实例，不定义进入、离开、完成或取消回调。运行时调度不使用 clips 来决定业务行为。

修改或删除片段不会自动生成、移动、删除或重新绑定 marks 和 listeners。标记不填写 clip_id，也不隐式归属于覆盖它的片段。

时间轴经过片段边界或阻塞在片段范围内，只影响游标在视觉上的位置，不代表业务事件进入、完成或暂停。当前不引入根据脚本状态自动伸缩片段的逻辑。

字段 label、handler、script、method、condition 和业务参数不属于 clips。名称“事件段”仅用于编辑器中的视觉表达。

## 9. 有时间点的标签标记

输出标记和阻塞输入标记都保存在轨道的 marks 数组中。

### 9.1 共有字段

| 字段 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| id | int | 是 | 程序分配 | 文档内唯一的标记标识 |
| name | string | 否 | label | 编辑器显示名称 |
| time | integer | 是 | 无 | 标记的时间位置，单位为 0.1 秒 |
| kind | string | 是 | 无 | output 或 blocking |
| label | string | 是 | 无 | 输出的标签，或期待的输入标签 |

kind 已经表达方向，不额外保存 direction 字段。

当前只支持这两种有时间点的标记。旧方案中的 TRIGGER、INTERVAL、EXTERNAL、GATE，以及 condition、dependencies、late_policy，不沿用到当前 JSON。

### 9.2 输出标签

~~~json
{
  "id": 6,
  "name": "引导完成",
  "time": 100,
  "kind": "output",
  "label": "intro_finished"
}
~~~

含义：时间轴经过 10.0 秒位置时，发出 intro_finished 标签。

输出配置只有标签。target、payload、handler、script、method 和处理类参数都不属于这个标记。

如果需要实际触发某段表现的进入和离开，可以放置两个普通输出标记，分别发出两个标签。这两个标记与视觉片段相互独立，JSON 不从片段边界自动推导标签或业务生命周期。

### 9.3 阻塞输入标签

~~~json
{
  "id": 7,
  "name": "等待解谜完成",
  "time": 150,
  "kind": "blocking",
  "label": "puzzle_completed"
}
~~~

含义：时间轴到达 15.0 秒位置时，检查本次运行是否已收到期待的 puzzle_completed 标签。尚未收到则停在该位置等待，收到后解除该标记的等待。

time 表示检查和等待的位置，不要求标签恰好在这一时刻产生。

收到标签的记录、标记是否已通过、等待状态均由运行时维护，不写入 JSON。复杂业务判断和额外处理由程序定义。

## 10. 无时间点的全程输入标签

全程输入保存在时间轴的 listeners 数组中，在编辑器顶部或其他固定区域显示。

| 字段 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| id | int | 是 | 程序分配 | 文档内唯一的输入标识 |
| name | string | 否 | label | 编辑器显示名称 |
| label | string | 是 | 无 | 持续接收的输入标签 |
| enabled | boolean | 否 | true | 是否启用该输入 |

~~~json
{
  "id": 13,
  "name": "紧急中断",
  "label": "urgent_interrupt",
  "enabled": true
}
~~~

全程输入不填写 time、start、end 或轨道位置。等待标签期间不阻塞时间轴；收到标签后，由代码绑定的处理逻辑决定响应行为。

例如 urgent_interrupt 可以在程序中绑定暂停处理类，但 JSON 不保存“暂停”动作，也不保存该处理类。

默认有效期是本次时间轴启动到停止或完成，暂停和阻塞等待期间继续接收。删除或禁用该输入后，这条时间轴不再通过该入口处理对应标签，其他时间轴的同名输入不受影响。

~~~

示例中的视觉事件段和所有输出标签、阻塞输入标签、全程输入标签均由文件直接保存。全部对象共用 ID 1 至 18，id_counter 为 18，下次分配的 ID 为 19。“解谜阶段”的长度和解谜处理实例的实际执行时长没有自动对应关系；“氛围表现”的边界也不会替代 ambient_enter 和 ambient_leave 输出标记。实际标签绑定到哪些处理类，由配套的程序决定。

最小的可编辑文档也使用相同结构：

~~~json
{
  "name": "新时间轴文档",
  "id_counter": 2,
  "clocks": [
    {
      "id": 1,
      "mode": "manual"
    }
  ],
  "timelines": [
    {
      "id": 2,
      "clock_id": 1,
      "tracks": [],
      "listeners": []
    }
  ]
}
~~~

## 12. 字段与导入校验

建议使用明确的字段白名单，不静默接收已被移除的字段，也不在导出时悄悄丢弃无法识别的内容。

校验至少覆盖：

1. 根对象、数组和字段类型正确；必填字段存在；枚举值正确。
2. 标记 time 和片段 start 为非负整数，片段 duration 与时间轴有限 duration 为正整数，实时 rate 大于 0。
3. 所有配置对象的 id 均为正 int，在整份文档内共同唯一，不按类型或时间轴分别编号。
4. id_counter 为非负 int，不能小于文件中已存在的最大 ID；大于最大 ID 时合法，表示曾有对象被删除等情况。分配溢出仍仅按自增结果为负数检查。
5. clock_id 引用有效；标记时间和片段结束位置不超出有限时长。
6. label 是非空字符串，不含首尾空白。标签按完整字符串、大小写敏感匹配，不隐式重命名；数字 ID 由程序维护。
7. 所有输出、阻塞输入和全程输入都保留 label；listeners 不包含时间位置。
8. clips 的 name 非空，color 符合 #RRGGBB；片段不包含标签、脚本或业务生命周期字段。
9. 文件不包含事件管理器、绑定、类名、脚本路径、方法名和运行时状态。视觉事件段定义属于允许的编排数据。

标签字符串可以重复使用。重复标签与重复对象 id 是不同概念。同一标签对应多处输入时的消息消费规则见事件方案的待确认项。

程序标签目录和 JSON 不一致属于接入诊断，不是 JSON 语法错误。编辑器应保留原标签并提示问题，不根据当前程序环境删除配置。

加载、编辑和导出必须完整保留全部视觉事件段、标签、禁用项、轨道顺序及 id_counter。可以补全可选默认值，但不得重新编号、回退计数器、改变标签含义或把处理绑定写回文件。

## 13. JSON 与压缩 JSON

建议开发期间以可读 JSON 为默认形式，便于版本控制和人工检查。

如果后续增加压缩存储，解压后的正文仍然使用本方案的同一结构。压缩属于文件容器，不增加 JSON 字段，也不把事件系统放入压缩正文。

压缩算法、扩展名和是否需要实现导出暂未确定，本次不定义另一套压缩 JSON 数据结构。

这里的读写指编排文档读写，不包含游戏运行进度保存和恢复。

## 14. 尚待确认的运行细节

以下问题不通过新增 JSON 配置绕开，需要在运行时设计中继续确定：

- 共享时钟中的某条时间轴阻塞后，该时间轴恢复时如何映射自身进度与时钟进度。
- 一次推进跨过阻塞点时，未使用的推进量是保留还是丢弃。
- 同一时间点的输出、阻塞检查和消息回调的完整处理次序。
- 多个阻塞标记期待同一标签时，一条消息是否可以同时满足它们。
- 全程输入与阻塞输入期待同一标签时的分发关系。
- 提前收到任务结果时，如何区分同名标签代表的不同任务执行。
- time 为 0 的启动标记、位于结束边界的标记，以及跳转时的触发策略。

当前 JSON 已能表达这些位置和标签，但本方案不把上述未确认行为标记为已实现或已定案。
