# 序幕场景组织

序幕的 `main.tscn` 只保留 `PrologueMain` 根节点。它负责加载 C++ 状态机、装配可编辑场景、连接信号和投影状态；桌面、窗口、登录页和动态控件的视觉结构不再在 C# 中创建。

## 场景层级

```text
main.tscn
└── PrologueMain (script/PrologueMain.cs)
    ├── PrologueDesktop (content/prologue/scenes/prologue_desktop.tscn)
    │   └── CRTViewport / ContentViewport
    │       └── DesktopContent (desktop_content.tscn)
    │           ├── Wallpaper / DesktopShade
    │           ├── DesktopIcons
    │           │   ├── chat / browser / board (desktop_app_icon.tscn)
    │           ├── WindowLayer
    │           ├── Toasts
    │           └── Taskbar (taskbar.tscn)
    ├── chat / browser / board (运行时加载的窗口场景)
    ├── ImageLightbox (image_lightbox.tscn)
    ├── LockScreen (lock_screen.tscn)
    └── NVPrologueState (C++ GDExtension 节点)
```

## 运行时职责

`PrologueMain.cs` 只做以下工作：

- 使用 `GD.Load<PackedScene>()` 加载上述资源并把窗口放入 `WindowLayer`。
- 连接场景节点已有的按钮、输入框、拖放区和 CEF Host。
- 用 `ChatMessageView` 实例化消息，将白板快照和语义动作交给独立的 `BoardView`。
- 把 C++ `NVPrologueState` 的快照写入场景节点；剧情规则不在 UI 场景或 C# 中复制。

窗口位置、尺寸、标题栏样式、登录卡布局、任务区留白和 CRT 参数应优先在对应 `.tscn` 或插件资源中调整。C# 只在确实由状态或玩家操作决定的地方修改文本、可见性、纹理和窗口层级。

浏览器正文由独立 `BrowserView` 组件管理。`PrologueMain` 连接组件提交的语义动作，组件根据 C++ 的 `browser_resource` 在夜航搜索、暗涌论坛、街坊告示三个独立 HTML 文档之间切换；原生外壳不提供“论坛搜索范围”按钮。站点数据、帖子与后续调整方式见 [浏览器与暗涌网站.md](浏览器与暗涌网站.md)。

## 白板场景

`board_window_content.tscn` 的 `BoardContentRoot` 挂载 `BoardView.cs`。工具栏、画布背景、任务标题、框选层、任务图层和线索图层都在场景中；白板窗口仍通过 `window_chrome.tscn` 的 Body 插槽组合它。

```text
BoardContentRoot (BoardView)
├── Toolbar
│   └── Buttons (缩放、旋转、聚焦、全览、重置和读数)
└── BoardCanvas (BoardCanvasView)
    ├── Background
    ├── BoardWorld
    │   ├── Links (BoardLinksView)
    │   ├── TreeTitle
    │   ├── TaskLayer (task_drop_zone.tscn 实例)
    │   └── ClueLayer (clue_card.tscn 实例)
    └── Marquee
```

`BoardView` 根据 JSON 任务和 C++ 快照计算任务树与自由卡片的初始位置；卡片的自由坐标、缩放、旋转和批注以及白板平移、缩放、角度、自动全览状态由 C++ 状态机保存。任务匹配仍只由 C++ 判定。调整卡片尺寸、层级、配色、手柄和任务投放区样式时，直接编辑各自的 `.tscn`；树宽、缩进和间距通过 `BoardView` 的导出属性调整。已存在的卡片实例在快照更新时复用，其他线索收录不会清除正在编辑的批注或文字选区。

空白处左键或中键拖动可平移，滚轮围绕鼠标缩放，按住 Shift 或 Alt 滚轮可旋转，Ctrl+左键拖框可放大所框区域，双击空白处可全览白板。按题头或边缘拖动线索卡，按松手时的鼠标位置决定是否放入任务区；摘录与图片说明可划选并用 Ctrl+C 复制。双击题头可聚焦，选中后可用独立手柄旋转/缩放，在批注框编辑文字。轻点图片只放大已有原图，拖动图片则移动卡片，白板灯箱不提供重复收录按钮。

白板持有键盘焦点时，F 全览、R 归零整板角度、Esc 取消选中、Delete/Backspace 移除选中卡片；编辑批注或存在文字选区时不会误删卡片。“整理”会恢复自动排布与单卡变换，并保留批注、任务归属和答对记录。关闭/重开窗口保留本轮运行状态；重新开始序幕会清空，不额外写入磁盘存档。

任务行为对齐网页 `app-notes.js` 的两段状态：命中任务关键词就划掉子任务，拖走或移除线索不撤销答对记录；两条子任务全答对只表示可报告，主任务仍未完成。找猫交接结束后才划掉主任务、收起子任务，并将原先挂接的卡片散回自由区；原本自由摆放的卡片保留玩家坐标。

白板快照、卡片布局校验和完整找猫流程由 `test/PrologueStateIntegrationTest.tscn` 覆盖；这个场景也会加载白板模板检查运行时装配。`test/BoardInteractionIntegrationTest.tscn` 通过真实 Viewport 输入分发验证拖动、旋转/缩放手柄、批注保留、选字保护、图片点击/拖动、任务投放、平移、滚轮、框选和整理。可在带渲染的 Godot 运行中追加 `-- --capture-board --capture-desktop`，分别向 `artifacts/board-preview.png`、`artifacts/board-desktop-preview.png` 写出独立组件与真实 CRT 桌面中的验收图。
