# 浏览器与暗涌网站

## 网站层级与原型口径

浏览器是 Godot 的应用窗口；夜航搜索、街坊告示和暗涌是其中加载的独立网页。通常路径是：夜航搜索输入“暗涌”→打开 `https://anyong.bbs/`→在论坛内输入“猫”→打开具体帖子。猫帖只参与站内搜索，其他未标记 `forum_only` 的帖子可以参与全网搜索。

对照原型 `app-browser.js` 的 `search/openForum/renderPosts/openThread` 与 `data.js` 的论坛定义：启事收录完成后才出现林越推荐论坛的对白，网站和猫帖本身不要求先收录。当前导入开局可见的七帖：版规、夜班规矩、借寿、电梯、山雾、弹珠、捡猫。后续案件的帖子和私信规则随对应剧情迁移，本次不预放未来内容。

## 后续调整内容

`forum` 保存站点字段 `id/site/title/url/slogan/page_resource/search_keywords/search_excluded_terms/categories/posts`。站名关键词用于发现网站，`search_excluded_terms` 用于从帖子搜索文本中排除站名；替换站点品牌时一起修改这两组数据。

新增帖子时复制 `forum.posts` 中的条目，填写唯一的 `id`、`url`、`title/category/author/time`、正文和可选图片，分类值应存在于 `forum.categories`。`pinned/replies/views` 控制列表表现；顺序采用数据中的数组顺序。正文和楼层无需另写 C++ 分支。

- `forum_only: true`：只在站内检索，始终不出现在全网结果。
- `floors[].no_search: true`：这层回复可读，但不参与该帖的检索。
- `floors[].requires_complete: true`：找猫交接完成后才显示且参与检索，用于失主领走的收尾楼。
- `pet.forum_post_id`：找猫目击帖的稳定 ID，仅该帖置位找猫的已读里程碑；改名或换帖子时同步修改。
- `short_source/image/image_caption`：进入白板和灯箱的来源与图片数据。不同帖子的摘录通过 `post_id` 区分。

目前 `requires_complete` 对应本序幕的交接完成条件；后续章节有其他显示条件时，应由 C++/流程插件提供对应内容投影。网页继续接收已经裁定的可见内容。

浏览历史只保存路由、结果和查询上下文；后退不会撤销白板卡、已读标记或任务，重新开始序幕则清空这些运行状态。未知地址和无效帖子返回明确失败，不跳往替代页面。C++ 中文 `String` 常量使用 `U"中文"`，因为 godot-cpp 的 `const char*` 构造采用 Latin-1。

## 验证入口

- `test/PrologueStateIntegrationTest.tscn`：独立站点、搜索边界、提前浏览、多帖来源、分类、回复搜索、历史、无效地址和完整找猫流程。
- `test/PrologueBrowserIntegrationTest.tscn`：实际 BrowserView 和 CEF 往返，覆盖跨站加载、真实 DOM 搜索与选区、图片解码、原生导航、提前浏览及完成后的收尾楼，还检查真实 CRT 桌面中的浏览器装配。
- `test/BoardInteractionIntegrationTest.tscn`、`test/DesktopUiRegressionTest.tscn`：白板交互与桌面窗口回归。

本机使用 `F:\Godot\godot\bin\godot.windows.editor.x86_64.mono.console.exe` 执行验收，它是指定 Mono 编辑器的控制台入口。CEF 验收需带实际渲染运行；追加 `-- --capture-browser` 可在 `artifacts/` 导出论坛首页、猫帖和实际桌面截图。
